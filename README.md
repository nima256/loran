# لوران | Loran

فروشگاه اینترنتی کفش **لوران** (یزد) — فارسی، راست‌به‌چپ، با حالت روشن و تیره.

یک برنامه‌ی Next.js (App Router) با بک‌اند کامل: PostgreSQL + Prisma، ورود با کد یک‌بارمصرف
ملی‌پیامک، پرداخت زرین‌پال، و پنل مدیریت تک‌مدیره. قیمت، موجودی و تخفیف **همیشه** سمت سرور
محاسبه می‌شوند؛ هیچ عددی از مرورگر پذیرفته نمی‌شود.

---

## راه‌اندازی محلی

نیازمندی: Node.js 20 یا بالاتر و یک PostgreSQL 14+ در دسترس.

```bash
npm install
cp .env.example .env          # سپس مقدارها را پر کنید (پایین را ببینید)
npm run db:migrate:dev        # ساخت جدول‌ها
npm run db:seed               # کاتالوگ، دسته‌بندی‌ها، روش‌های ارسال و حساب مدیر
npm run dev                   # http://localhost:3000
```

برای توسعه محلی می‌توانید `OTP_MOCK="true"` و `PAYMENT_MOCK="true"` بگذارید تا کد تأیید در
پاسخ API برگردد و پرداخت بدون تماس با درگاه «موفق» شود. هر دو در تولید **ممنوع**‌اند؛
برنامه با روشن بودنشان در `NODE_ENV=production` بالا نمی‌آید.

حساب مدیر از `ADMIN_EMAIL` و `ADMIN_PASSWORD` ساخته می‌شود. اجرای دوباره‌ی `npm run db:seed`
رمز را به همان مقدار بازنشانی می‌کند — این مسیر بازیابی رمز فراموش‌شده است.

### بررسی‌ها

```bash
npm run typecheck
```

## اجرای تولیدی

متغیرهای محیطی از `.env.example` گرفته می‌شوند. مقدارهای الزامی در تولید:

| متغیر | توضیح |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | رشته اتصال PostgreSQL |
| `SITE_URL` | دامنه عمومی، حتماً `https://` و بدون `/` پایانی (آدرس بازگشت زرین‌پال از آن ساخته می‌شود) |
| `SESSION_SECRET` | حداقل ۳۲ کاراکتر — `openssl rand -base64 48` |
| `OTP_SECRET` | حداقل ۳۲ کاراکتر، متفاوت از `SESSION_SECRET` |
| `MELIPAYAMAK_SHARED_KEY` | کلید اشتراکی کنسول ملی‌پیامک |
| `MELIPAYAMAK_OTP_BODY_ID` | شناسه الگوی پیامک کد ورود (یک آرگومان: کد) |
| `ZARINPAL_MERCHANT_ID` | مرچنت‌آیدی زرین‌پال — **فقط متغیر محیطی سرور** |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | برای ساخت یا بازنشانی حساب مدیر هنگام seed |
| `UPLOAD_DIR` | مسیر ذخیره تصاویر محصول؛ باید روی حجم ماندگار باشد، نه دیسک موقت کانتینر |

اختیاری ولی معمول: `MELIPAYAMAK_ORDER_BODY_ID` و `MELIPAYAMAK_SHIPPED_BODY_ID`
(پیامک ثبت سفارش و ارسال مرسوله)، `TRUST_PROXY="true"` وقتی برنامه واقعاً پشت یک
reverse proxy است، `ZARINPAL_AMOUNT_UNIT` اگر حساب درگاه ریال می‌خواهد،
`COOKIE_SAMESITE`، `SESSION_TTL_DAYS`، `ADMIN_SESSION_TTL_HOURS`.

`src/server/lib/env.ts` این‌ها را هنگام بالا آمدن اعتبارسنجی می‌کند: اگر رازی کوتاه یا جا
افتاده باشد، `SITE_URL` آدرس امن نباشد، یا حالت‌های mock روشن مانده باشند، برنامه بالا
نمی‌آید — به‌جای آنکه سر اولین پرداخت خراب شود.

### دستورهای بیلد و اجرا

```bash
npm ci
npm run db:migrate        # prisma migrate deploy — مهاجرت‌ها روی دیتابیس تولیدی
npm run build             # prisma generate && next build
npm run start             # next start -p 3000
```

`npm run db:seed` را در تولید فقط یک‌بار (برای کاتالوگ اولیه و حساب مدیر) اجرا کنید؛
seed با upsert نوشته می‌شود و اجرای دوباره داده‌ای را تکرار نمی‌کند، اما رمز مدیر را بازنشانی می‌کند.

> میزبانی، دامنه و پیکربندی سرویس ابری بیرون از این مخزن است و عمداً پیاده‌سازی نشده.

## نکته‌های مهم مدل داده

- **موجودی روی «تنوع» است، نه محصول.** هر `ProductVariant` ترکیب یک رنگ و یک سایز است و
  `stock` خودش را دارد. کل رابط کاربری (صفحه محصول، سبد، انبار، ماتریس پنل مدیریت) بر همین
  اساس ساخته شده؛ حالت «مشکی/۴۱ موجود، مشکی/۴۲ ناموجود، سفید/۴۲ موجود» حالت عادی است.
  کم شدن موجودی با یک `UPDATE … WHERE stock >= qty` اتمیک انجام می‌شود، پس دو سفارش هم‌زمان
  آخرین جفت را نمی‌برند.
- **قیمت‌ها عدد صحیح تومان‌اند.** هیچ‌جا اعشار یا ریال استفاده نشده.
- **زنجیره‌ی قیمت‌گذاری یک‌جا و سمت سرور است** (`src/server/services/pricing.ts`):
  قیمت پایه ← کمپین فعال ← قیمت اختصاصی تنوع ← کد تخفیف روی جمع سبد ← هزینه ارسال.
  قیمتی که مرورگر می‌فرستد فقط برای *تشخیص تغییر قیمت* به کار می‌رود، نه برای محاسبه.
- **هزینه ارسال تیپاکس پس‌کرایه است** و عمداً از `payableOnline` کنار گذاشته شده.
- **سفارش‌ها «عکس لحظه‌ای» نگه می‌دارند.** نام، نشانی، قیمت و روش ارسال روی خود سفارش ذخیره
  می‌شوند تا ویرایش بعدی محصول یا آدرس، فاکتور قدیمی را تغییر ندهد.
- **بازگشت از درگاه ایدمپوتنت است.** `paymentAuthority` یکتاست و `finalizedAt` نگهبان نهایی‌سازی
  است؛ چند بار فراخوانی شدن callback موجودی را دوبار کم نمی‌کند و کد تخفیف را دوبار خرج نمی‌کند.
- **وضعیت‌های سفارش** یک گذارنامه‌ی مشخص دارند (`src/server/services/order-status.ts`):
  پنج وضعیت اصلی تایم‌لاین را می‌سازند و وضعیت‌های استثنا (لغو، مرجوعی، بازپرداخت، پرداخت
  ناموفق، منقضی) بیرون از تایم‌لاین نمایش داده می‌شوند.

## نکته‌های امنیتی

- کد یک‌بارمصرف هرگز به‌صورت خام ذخیره یا در تولید لاگ نمی‌شود؛ با HMAC و یک راز سمت سرور
  و مقیدشده به شماره‌ی موبایل نگهداری می‌شود.
- نشست مشتری و نشست مدیر دو کوکی و دو جدول جدا دارند و هنگام ورود چرخانده می‌شوند.
- مرچنت‌آیدی زرین‌پال فقط از متغیر محیطی خوانده می‌شود: نه به مرورگر می‌رسد و نه در فرم
  تنظیمات پنل قابل دیدن یا ویرایش است. پنل فقط می‌گوید «تنظیم شده / نشده».
- تصویرهای آپلودی با sharp رمزگشایی و دوباره به WebP کدگذاری می‌شوند (اعتبارسنجی بر پایه‌ی
  محتوا، حذف EXIF، نام فایل ساخته‌ی سرور).
- محدودیت نرخ روی درخواست کد، ورود مدیر، ثبت دیدگاه و فرم‌های عمومی، در PostgreSQL.

## دارایی‌های برند

- `public/brand/loran-logo.png` — لوگوی اصلی ارسالی (دست‌نخورده)
- `loran-mark*.png` / `loran-wordmark*.png` — همان لوگو، جدا شده به نشان و لوگوتایپ و در دو
  رنگ برند. با `node scripts/extract-logo-masks.mjs` دوباره ساخته می‌شوند. لوگو بازطراحی نشده؛
  فقط رنگ مرکب آن بین حالت روشن و تیره عوض می‌شود.
- `loran-business-card.png` / `homepage-wireframe.webp` — مرجع طراحی.

### تصاویر محصول

`public/products/*.svg` تصویرهای **برداری موقت** هستند که با
`node scripts/generate-product-images.mjs` ساخته می‌شوند: شش فرم کفش × دوازده رنگ × چهار زاویه،
همگی مربعی (۱:۱) و با قاب‌بندی یکسان — به همین دلیل شبکه محصولات هنگام تغییر رنگ یا صفحه نمی‌پرد.

برای جایگزینی با عکس واقعی: فایل‌ها را با همین نام‌ها در `public/products/` قرار دهید،
یا مسیرها را در `src/data/catalog.json` (میدان `colors[].images`) عوض کنید. هیچ کامپوننتی
مسیر تصویر را hard-code نکرده است.

## تصمیم‌های طراحی

- **دیزاین سیستم در `globals.css`.** رنگ‌ها توکن معنایی‌اند (`--surface`، `--fg-muted`،
  `--primary`)، نه کد رنگ خام در کامپوننت‌ها. حالت تیره یک وارونه‌سازی نیست: خنثی‌ها گرم‌اند
  و رابطه «کرم روی زرشکی» لوگو حفظ شده. همه جفت‌های متن/پس‌زمینه دست‌کم ۴٫۵:۱ کنتراست دارند.
- **رنگ برند جیره‌بندی شده.** `#9A1C21` فقط برای اقدام اصلی، تخفیف و وضعیت فعال؛ `#EEE6DD`
  فضای گرم پس‌زمینه را می‌سازد. در هر ناحیه صفحه فقط یک دکمه «اصلی» وجود دارد.
- **موبایل بازطراحی شده، نه کوچک‌شده.** هدر موبایل ۵۶px است، ناوبری پایین پنج مقصد اصلی را
  دارد، فیلترها در شیت پایین باز می‌شوند و دکمه خرید چسبان فقط وقتی ظاهر می‌شود که دکمه اصلی
  از دید خارج شده باشد.
- **نمودارها تک‌رنگ‌اند.** هویت با برچسب مستقیم و متن محور منتقل می‌شود نه با رنگ، بنابراین
  نمودارها برای کاربران کوررنگ و در چاپ هم خوانا می‌مانند. هر نمودار نمای جدولی دارد.
- **دسترس‌پذیری.** فوکوس دیدنی در کل سایت، ناوبری کامل با صفحه‌کلید، تله فوکوس و بازگشت فوکوس
  در همه لایه‌های شناور، اندازه هدف لمسی حداقل ۴۴px، احترام به `prefers-reduced-motion`، و
  خطاهای فرم که با `aria-describedby` به فیلد وصل می‌شوند.
- **نامک محصول‌ها انگلیسی است** (`/product/loran-sepehr-562`) تا در اشتراک‌گذاری، لاگ و API
  به رشته درصدی ناخوانا تبدیل نشود. نام فارسی در عنوان صفحه و `<h1>` می‌آید.

## ابزارهای توسعه

```bash
node scripts/generate-catalog.mjs         # ساخت ۱۰۰ محصول ساختگی (قطعی و تکرارپذیر)
node scripts/generate-product-images.mjs  # ساخت تصاویر محصول
node scripts/extract-logo-masks.mjs       # جدا کردن نشان و لوگوتایپ از لوگو (نیازمند Pillow)
node scripts/audit.mjs 390 --auth /shop   # بررسی سرریز افقی، هدف‌های لمسی کوچک و خطاهای کنسول
node scripts/shoot.mjs out 390 full /shop # اسکرین‌شات (با ‎--dark برای حالت تیره)
node scripts/flow.mjs out 390             # پیمایش کامل مسیر خرید و عکس‌برداری از هر مرحله
```
